---
title: "Connect a client"
description: "Add the PlugKit MCP server to Claude, ChatGPT, Grok, Claude Code, Cursor, VS Code, or any other MCP client."
---

Every client needs the same thing — the server URL:

```
https://api.plugkit.co/mcp
```

Clients that support OAuth (all the ones below) will open a PlugKit consent
screen the first time they connect; approve it and you're done. There is no key
to paste unless you want one.

<Warning>
  **You add the connector yourself — not from a chat with the assistant.** An
  assistant asked to install its own connector will decline (it can't vouch for
  what it would be connecting to), and an API key pasted into a conversation
  connects nothing while staying in the history forever. Every
  step below is something you click or run; it takes about a minute. The
  [dashboard](https://plugkit.co/dashboard/mcp) walks through the same steps one
  client at a time and tells you when the server has seen your assistant connect.
</Warning>

## Claude (web, desktop, mobile)

<Steps>
  <Step title="Open the connector settings">
    In Claude, open [Customize → Connectors](https://claude.ai/#customize/connectors),
    then **Add → Custom connector**. On a phone, do this in Safari or Chrome at
    claude.ai, not in the Claude app; the connector then shows up in the app too.
  </Step>
  <Step title="Paste the URL">
    Name it `PlugKit` and paste `https://api.plugkit.co/mcp`. Leave the advanced
    OAuth fields empty — PlugKit registers the client automatically.
  </Step>
  <Step title="Connect and approve">
    Click **Connect**. Claude sends you to PlugKit, you sign in if needed, pick
    read-only or full access, and approve.
  </Step>
  <Step title="Check it">
    Ask Claude *"what PlugKit accounts do I have?"* — it should call `whoami`
    and list your profiles and connected accounts.
  </Step>
</Steps>

<Note>
  Custom connectors are available on Free, Pro, Max, Team and Enterprise plans;
  free accounts are limited to one custom connector.
</Note>

## ChatGPT

ChatGPT takes the same URL, as a custom MCP server on its **Plugins** screen.
Add it **in a browser** at chatgpt.com, on your computer or your phone (Safari,
Chrome). The ChatGPT app has no screen to add one.

<Steps>
  <Step title="Open the plugins screen in your browser">
    Go to [chatgpt.com/plugins](https://chatgpt.com/plugins#no_universal_links)
    and sign in. On an iPhone, a plain `chatgpt.com/plugins` link opens the
    ChatGPT app instead of Safari: use this link, or type the address in Safari.
  </Step>
  <Step title="Add a custom MCP server">
    Click the **+** in the top right, then **Add custom MCP server**.
  </Step>
  <Step title="Fill in the connection">
    Name it `PlugKit` and paste `https://api.plugkit.co/mcp` under **Server
    URL**. Pick **OAuth** and leave client id and secret empty: PlugKit registers
    ChatGPT itself. Tick **I understand** and create the plugin.
  </Step>
  <Step title="Approve, then use it">
    ChatGPT opens PlugKit: sign in if needed, pick read-only or full access, and
    approve. In a new chat, open the **+** menu and select **PlugKit**. Ask
    *"search my PlugKit account for the conversation about pricing"*. It should
    call `search`, then `fetch` on the result.
  </Step>
</Steps>

<Note>
  You need a paid ChatGPT plan (Plus, Pro, Business, Enterprise or Edu).
  Developer mode is no longer needed.
</Note>

<Note>
  ChatGPT expects every connector to expose two tools with fixed names, `search`
  and `fetch` — that is how it looks things up and cites them. PlugKit serves
  both, over everything the account holds: posts, conversations (by contact
  **and** by what was said in them), accounts, media, automations, sequences,
  broadcasts and playbooks. They are read-only, and every client gets them, not
  just ChatGPT.
</Note>

## Grok

Grok calls a custom MCP server a **connector**. It takes the same URL and signs
in with OAuth like the others.

<Steps>
  <Step title="Open the connectors screen">
    On [grok.com/connectors](https://grok.com/connectors), click
    **New Connector**, then **Custom**.
  </Step>
  <Step title="Paste the URL">
    Name it `PlugKit` and paste `https://api.plugkit.co/mcp` as the server URL.
    There is no client id or secret to fill in — PlugKit registers Grok itself.
  </Step>
  <Step title="Approve, then use it">
    Grok opens PlugKit: sign in if needed, pick read-only or full access, and
    approve. Then ask *"what PlugKit accounts do I have?"* — it should call
    `whoami` and list your profiles and connected accounts.
  </Step>
</Steps>

<Note>
  Custom connectors need a paid Grok plan (SuperGrok). Grok only accepts remote
  servers over Streamable HTTP or SSE, which is what PlugKit is — nothing to
  install.
</Note>

## Claude Code

```bash
claude mcp add --transport http --scope user plugkit https://api.plugkit.co/mcp
```

Then run `/mcp` inside Claude Code and choose **Authenticate** — it opens the
PlugKit consent screen in your browser. `--scope user` makes the server
available in every project; drop it to keep PlugKit to the current folder.

With an API key instead of OAuth:

```bash
claude mcp add --transport http --scope user plugkit https://api.plugkit.co/mcp \
  --header "Authorization: Bearer sk_your_key"
```

The three PlugKit workflows show up as slash commands:
`/mcp__plugkit__publish`, `/mcp__plugkit__inbox`, `/mcp__plugkit__report`.

## Any other client

The server speaks plain MCP over Streamable HTTP, so anything that can add a
remote server works — Windsurf, Zed, LibreChat, Goose, your own agent. The
canonical config shape:

```json
{
  "mcpServers": {
    "plugkit": {
      "type": "http",
      "url": "https://api.plugkit.co/mcp"
    }
  }
}
```

If the client doesn't do OAuth, add the header:

```json
{
  "mcpServers": {
    "plugkit": {
      "type": "http",
      "url": "https://api.plugkit.co/mcp",
      "headers": { "Authorization": "Bearer sk_your_key" }
    }
  }
}
```

### From your own code

Any MCP SDK works. With the TypeScript SDK:

```ts
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StreamableHTTPClientTransport } from "@modelcontextprotocol/sdk/client/streamableHttp.js";

const client = new Client({ name: "my-agent", version: "1.0.0" });
await client.connect(
  new StreamableHTTPClientTransport(new URL("https://api.plugkit.co/mcp"), {
    requestInit: {
      headers: { Authorization: `Bearer ${process.env.PLUGKIT_API_KEY}` },
    },
  }),
);

const { tools } = await client.listTools();
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="My assistant says it doesn't know PlugKit, or refuses to install it">
    Expected, and not a fault on either side: PlugKit is a *custom* connector, so
    it appears in no assistant's built-in list, and an assistant asked to install
    its own connector will decline — it has no way to vouch for what it would be
    connecting to. Follow the steps for your client above; the tools appear on
    their own once the server is added.

    If it asks you to confirm the service is legitimate before you connect, our
    only addresses are **plugkit.co**, **api.plugkit.co** and **docs.plugkit.co**.
    Once connected, this is a useful thing to paste to give it its bearings:

    ```
    I use PlugKit (https://plugkit.co) to manage my social accounts. Its MCP
    server is https://api.plugkit.co/mcp and its docs are at
    https://docs.plugkit.co/mcp/overview. I have already added it as a
    connector — please use its tools, starting with whoami.
    ```
  </Accordion>
  <Accordion title="Someone gave me an API key — where do I paste it?">
    Nowhere, for Claude, ChatGPT, Grok, Claude Code, Cursor and VS Code: they sign in instead,
    which is both easier and safer. A key is only for an app that can't open a
    sign-in window, or for your own code — it goes in a config file or an
    environment variable, never in a chat. A key carries full access and doesn't
    expire, so if one has been through a conversation, revoke it under **API
    keys** in the dashboard and create another.
  </Accordion>
  <Accordion title="The client asks for a command to run, or an SSE URL">
    PlugKit is a **remote** server: nothing to install, no `npx` command, no
    local proxy. Choose the client's HTTP / Streamable HTTP option and give it
    `https://api.plugkit.co/mcp`. Legacy SSE is not supported.
  </Accordion>
  <Accordion title="The client says 401 / unauthorized">
    The server is reachable but the token isn't valid. With OAuth, disconnect and
    reconnect the server so it runs the consent flow again. With an API key,
    check the header is exactly `Authorization: Bearer sk_…` and that the key
    hasn't been revoked in the dashboard.
  </Accordion>
  <Accordion title="Connected, but the tools do nothing useful">
    Ask the assistant to call `whoami` first. Almost every tool needs a
    `profileId` or an `accountId`, and `whoami` is what hands those out along
    with what each platform supports.
  </Accordion>
  <Accordion title="Only read tools show up">
    The token was granted `mcp:read`. Write tools are not registered at all for a
    read-only session — reconnect and grant full access if you want the assistant
    to publish and reply.
  </Accordion>
  <Accordion title="The client tries GET or SSE and fails">
    The server is stateless: it answers `POST /mcp` and returns JSON. `GET` and
    `DELETE` return `405`. Configure the server as **HTTP / Streamable HTTP**,
    never as legacy **SSE**.
  </Accordion>
  <Accordion title="A one-click button does nothing">
    The `cursor://` and `vscode:` links need the app installed on the same
    machine as the browser, and the browser may ask you to allow opening an
    external application. If it stays silent, fall back to the JSON config above.
  </Accordion>
</AccordionGroup>
